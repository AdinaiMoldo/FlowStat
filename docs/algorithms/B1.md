# B1. Content rules of a form (US-54)

Not a C function: the algorithm card of the step that checks what a regional form says.

## Problem

A form is rows of `code, name, value`. A statistician needs to know not only that a form is wrong
but where (the cell), why (the rule, with a code that does not change), what was found and what was
expected, and whether it blocks the form. The rules differ by template, and a missing figure must
never pass for a zero.

## Method (`model/rules.py`)

1. Each value cell is put in one state: empty, not applicable (`n/a`), invalid (text, a boolean, not
   finite), zero or a figure. A missing indicator is the fifth case and has no cell.
2. A float is read as the number that was typed: `Decimal(str(value))`, the shortest text that
   gives the same float back. So `0.1` is 0.1 and `0.1 + 0.2` is exactly `0.3`. Sums are made in a
   context of 700 digits, enough for any sum of floats, so they never round.
3. One pass over the rows finds the findings of a row (structure, state, negative, range). The
   figures that no rule refused are kept by code.
4. Then what is missing, then the relations (`part <= whole`) and the sums (`total == sum of
   parts`) over the kept figures only. A figure that was refused is not used again, so one wrong
   cell gives one finding and not a cascade.
5. The rule sets are data (`RuleSet`: indicators, relations, sums), not code. The basic set is
   empty; a template lists its indicators.

Cost: one pass plus one lookup per rule, O(rows + rules). Measured: 5,000 rows in 16 ms (basic) and
25 ms (template); a form of five rows in 14 microseconds.

## The input on which the plain version fails

Parts 0.1, 0.2 and 0.3 and a total of 0.6: the sum of the floats is 0.6000000000000001, so a plain
`total == sum(parts)` rejects a correct form. A tolerance such as `abs(a - b) < 1e-9` accepts a
total of 0.6000000001, which is wrong. The exact decimal accepts the first and rejects the second,
and says the gap.
