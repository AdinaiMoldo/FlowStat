# B2. Problems and what a new version does to them (US-56)

Not a C function: the card of the reconciliation that keeps the problems of a form up to date.

## Problem

A form with errors is sent, corrected, sent again, sometimes corrected wrongly. A list of findings
per version does not say who works on a mistake or what became of it. A problem is that
bookkeeping: one thing for one mistake, with a status, an assignee and a history.

## Method (`model/problems.py`, `reconcile`)

1. Only findings of severity ERROR count, and a mistake is the key `code|indicator` (the cell when
   there is no indicator), the same identity as the comparison of versions (A2). Findings with the
   same key are one mistake.
2. The errors of the new version are put in a map by key, once.
3. Each problem of the form is looked up in the map. An active problem (OPEN, REOPENED,
   REVALIDATING) whose key is not there is RESOLVED, through REVALIDATING; one whose key is there
   is REOPENED, through REVALIDATING, and takes the new cell and values. A RESOLVED problem whose
   key is back is REOPENED.
4. The keys that no problem has are the new mistakes: each opens a problem.
5. The result is a list of changes; the service writes them, each with its events (each write is
   its own commit; a crash in the middle leaves the next version to finish the work, because the
   comparison is made against what is stored).

Cost: O(n + m) for n problems and m errors. Measured on this machine, one reconciliation of n
problems against n/2 errors: 100 problems 0.07 ms, 1,000 problems 0.8 ms, 10,000 problems 10 ms. A
real form has five to fifty.

## The input on which the plain version fails

A form sent a second time with the same wrong value in another cell. A comparison by cell closes
the problem of C5 and opens a new one for C6, and the history of the work (who took it, what was
said) is lost on a mistake that was never corrected. By key, the problem stays, is REOPENED and
points to C6. The opposite input: a mistake that goes away and comes back two versions later. A
state that is only "open" or "closed" forgets the first fix; here it is RESOLVED, then REOPENED,
and both are in the history.
