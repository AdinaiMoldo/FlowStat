# A2. Versions of a form and what the newer one fixed (US-55)

Not a C function: the card of the comparison that the page of the forms shows.

## Problem

A region sends its form, sees an error, and sends it again. The first file must not be lost, and
both people (the operator of the region and the chief statistician) want to know whether the
mistake is gone, not to read two lists of findings side by side.

## Method (`model/form_versions.py`)

1. A version is a file that was accepted, numbered for the region and quarter. It keeps the
   findings that the rules gave at that time, so a later change of rules does not rewrite history.
2. The same file again (same SHA-256 as the current version) is not a version. A file on the disk
   whose hash is not that of the current version is not shown as one.
3. Two findings are *the same mistake* when the code and the indicator are the same (the cell when
   there is no indicator): a negative value that moved to another row is still there.
4. The comparison walks the older findings once and matches each with an unused finding of the
   newer one that has the same key. Matched: remaining. Not matched: fixed. What is left of the
   newer: introduced. A mistake that was there twice and is there once has one fixed.

Cost: O(n·m) in the findings of the two versions, which are tens, not thousands.

## The input on which the plain version fails

A set difference of findings by cell says that moving a wrong value from C5 to C6 fixed one mistake
and brought one, and the region sees "fixed" for a form that is still wrong. A difference by code
alone says that a second negative value in another indicator is "still the same". Matching by code
and indicator, one to one, says neither.
