# M7. IDE and service view

Status: done (9 November 2026), tag `m7` to be created after merge. Size: 21 SP (US-26, US-27, US-28, US-31).

## Goal

A designer works in a browser and not in a text file: she types a workflow, a marker appears at the
position of an error half a second after she stops, completion inside `${` offers only the data that
is guaranteed at that step, and a preview draws the workflow as a graph. An administrator sees the
runs of a deployed service in the core: the service ships the events of its runs to the core, the
core stores them once even if a batch arrives twice, and the registry shows the version, the
endpoint and the status of every service. The editor and the preview are served by the core itself,
so the contract of M6 does not change for them: they are clients of it.

## Stories

| Story | Function | SP | Given / When / Then |
| --- | --- | --- | --- |
| US-26 editor with live diagnostics | B2 | 8 | Given an error is typed, when I pause for 500 ms, then a marker appears at its position |
| US-28 graph preview | B3 | 5 | Given a valid workflow, when I open the preview, then every step instance is a node and every dependency an arrow; conditional steps are marked and fan-out instances are grouped |
| US-27 completion | B2, C2 | 3 | Given the cursor is inside `${` in step c, when I request completion, then only inputs and outputs of steps guaranteed at c are suggested |
| US-31 service runs in the core | A6, A2 | 5 | Given a deployed service completes a run, when its outbox ships the events, then the core shows the history. Given the same batch is delivered twice, then no duplicate events appear. The registry shows version, endpoint and status |

## Readiness audit (9 November)

The milestone was checked against the Project Proposal (B2, B3, A2, A6), against `api-spec.md`, the
code of M6 (`api/`, `service/`, `repo/runs.py`, `analysis/availability.py`) and against the tools of
this environment before the first line of code. Twenty gaps were found. Each is closed in
`api-spec.md` (section 9) or in the order of work below.

1. **There is no browser client and no way to serve one.** The core serves JSON only. Closed: the client is a few static files in `src/flowstat/api/ui/` (one HTML page, one script, one style sheet, no build step) served by the core at `/ui/`. The files hold no data and no secret, so they are public; every call they make goes through the routes of M6 with a token.
2. **CORS was left to M7 "with the IDE".** A page served by the core calls the core on the same origin, so CORS is not needed and stays off. A browser application on another origin is out of scope (it would need an allow-list of origins, which is a deployment decision). Closed: written in `api-spec.md` section 9.
3. **Monaco and Cytoscape cannot come from a CDN here, and a demonstration may be offline.** The sandbox refuses `cdn.jsdelivr.net`; the npm registry is reachable. Closed: `scripts/fetch_ui.py` (standard library only) downloads the four pinned packages from the npm registry, checks the SHA-512 of each tarball against the value written in the script, and unpacks only the files the page loads into `src/flowstat/api/ui/vendor/`, which is ignored by git. The versions are those of `reuse.md` (Monaco 0.57.0, Cytoscape 3.34.4, dagre 0.8.5, cytoscape-dagre 4.0.1). Without the vendor folder the page still opens, edits in a plain text area, shows the same diagnostics as a list and says how to fetch the editor.
4. **A diagnostic has a line and a column and no end.** A marker needs a range. Closed: the client marks the word at the position (to the end of the token), or one character when there is none; the server does not invent a range.
5. **`POST /validate` stores nothing and needs `workflows:write`.** That is right for an editor (an operator has no use for one), and the page asks for a token of a designer or an admin. Closed: the page has a token box, keeps the token in `sessionStorage` (one tab, gone when it is closed), never in the address and never in `localStorage`.
6. **A draft that is being typed is almost always invalid.** The compiler leaves no plan when there is an error, and completion needs a plan. Closed: the server cuts the unfinished reference at the cursor (`${` up to the cursor) and compiles that text; if it still does not compile, the answer is an empty list and a note that names the first error. It never guesses from a text it cannot compile. Stated as a limit.
7. **The cursor is a line and a column of the text; completion needs a step.** The step is the last step of the source text that starts at or above the cursor line (`PlanStep.line` is the source map). A cursor above the first step or outside `steps:` has no scope and gets inputs only.
8. **`available_at` exists (M5) and takes a step id, not a base step.** A `foreach` base step has one instance per code. Closed: the instances of one base have the same `needs` shape, so the first instance stands for the base; a test checks this on the example with nine regions. Outputs of a `foreach` step are offered as `name[*]` (the list of all instances) and `name[var]`.
9. **Completion for fields.** What follows `${step.` is the fields the action declares for its output; an action without a declared schema offers none. Closed: fields come from `Signatures` (the same source the type checker uses); nothing is invented.
10. **"Guaranteed" is the sufficient condition of C2.** A step that is not guaranteed is left out of the list, and a test asserts that every suggestion gives no `W-AVAIL-001` when it is used. That is the story, tested as written.
11. **The graph has no serialised form.** Closed: a pure function `service/graph.py` turns a `Plan` into nodes and edges (id, base, action, line, conditional, goal, group, layer) and the client draws it; the layout (dagre) is the client's, the layer number is computed on the server so that the test can check the shape without a browser.
12. **Fan-out would make the graph unreadable.** Nine regions give 22 steps, a hundred regions give about 200 nodes. Closed: instances of one base are drawn inside a group node; the group can be collapsed; the page collapses a group of more than 12 instances. Measured in the note of this milestone.
13. **The editor needs a preview of an unsaved text.** Closed: `POST /graph` takes a text (permission `workflows:write`, like `/validate`) and answers `{diagnostics, graph}` with `graph` null when the text has errors, so the page keeps the last good graph and shows the errors. `GET /workflows/{name}/versions/{n}/graph` does the same for a stored version (`workflows:read`).
14. **The core does not know the runs of a service.** `runs` has no origin and a service's events were never shipped. Closed: the column `origin` (null for a run of the core, the deployment id otherwise), added by the same `_add_missing_columns` that older databases already use; the list of runs takes `deployment=<id>` and every run says its origin.
15. **How does a service prove who it is to the core?** A service is not a user. Closed: each deployment gets a third key, the *ingest key*, made with the other two and shown once; only its SHA-256 is stored, in the `deployments` table. The permission `events:ingest` belongs to no role, so the walk of the routes shows 403 for admin, designer and operator and 401 without a token, and a separate test shows the right key accepted and the key of another deployment refused. The plain key reaches the service through its environment (`FLOWSTAT_INGEST_URL`, `FLOWSTAT_INGEST_KEY`) and is never written into the bundle, which stays on disk.
16. **At least once needs a cursor that survives a restart.** Closed: `outbox(run_id, shipped_through)` in the service's own database, written only after the core has acknowledged; a restarted service continues from it. If the core lost data and answers "expected 40, got 55", the service moves its cursor back to 40 (the core says what it has). The log of the service stays the source of truth (architecture.md); the cursor is only a position in it.
17. **The shipper must never slow or stop a run.** Closed: it is a thread of the service app with an injected clock and sleep, it reads the log and sends in batches of at most 200 events, it backs off when the core does not answer (1 s, doubling, up to 30 s) and a failed send changes nothing. The logic is `service/outbox.py` with a `send` function passed in, so it is tested without a network and without a thread; the thread is a few lines at the edge.
18. **The first batch of a run must carry what the core needs to hold it.** `RunStore.append` refuses a run it does not know. Closed: a batch is `{run: {run_id, workflow, version, inputs, created_at}, events: [...]}`; the core creates the row once (`origin` = the deployment) and refuses a batch whose workflow and version differ from the deployment's (422) or whose run id is a run of the core (409).
19. **A container reaches the core only if the core listens where the container can go.** The core listens on 127.0.0.1 by default, which a container on the bridge network cannot reach. Closed as a stated limit and an option: `--ingest-url` of `python -m flowstat.serve` names the URL a service must use (default: the URL of the core on 127.0.0.1, right for a process); for a container the user starts the core with `--host 0.0.0.0` and an `--ingest-url` the container resolves (`host.docker.internal`, and the launcher adds the `host-gateway` entry). The process path is tested end to end; the container path is tested for the environment it passes, and the end-to-end run is done on the Ubuntu runner only if it fits in the time of the CI.
20. **Browser tests.** The editor's 500 ms and the marker are behaviour of a browser. Closed: tests marked `browser` use Playwright (already in the sandbox) against a real server and the vendored editor, and skip when Playwright or the vendor folder is missing; CI on Linux installs Chromium and runs them. The server side of every story is also tested without a browser (the routes, the graph function, the scope, the outbox).

Left out on purpose: saving from the editor on a timer, several users in one document, a diff between versions, syntax highlighting beyond what Monaco's YAML mode gives, a login page with passwords, the live update of the run list (the page asks again when the person asks), the health probe of a service from the registry (the status is the one recorded at start and stop; a row can still say `running` after a machine restart, carried to M8), the plan cache (M8). The tests of the server side are written before the code they test where the code is not trivial glue (the scope, the outbox, the ingest).

## Review

Delivered against the goal: a designer works in a browser, an administrator sees the runs of deployed services in the core. A marker appears at an error half a second after typing stops (one request per burst of edits, answers for an older text dropped); `${` offers exactly the data that is guaranteed at that step (checked both ways: every offered output is read without a warning, and the plain ancestors that are not offered do give `W-AVAIL-001`); the preview draws every step instance and every dependency, marks conditional steps and goals, groups a fan-out and collapses a large one; and a service that completes a run ships its history to the core, which shows it, stores it once and says in the registry which version runs where and when it last sent something.

Measurements: 1,873 tests (1,872 where the container test skips), 96.9% coverage (gate 90%), 23 tests in a real Chromium, CI green on Linux and Windows for each story. A completion request costs 4 to 5 ms, a batch of 200 events 6 ms, the graph of a hundred regions is built in 0.4 ms and drawn in 130 ms (`research/m7-measurement.md`). The OpenAPI files of the core and of the service are golden files and changed as the contract says (the core: the new route, the origin, the counts, the third key; the service: one optional field, `expected`, of the common error item).

What was and was not verified: the process path of US-31 was run for real (a service process, a core on a thread, HTTP between them, the key in the environment). The container path is tested for what it passes to Docker (the environment, a loopback address rewritten to `host.docker.internal`, the `host-gateway` entry), not end to end: it needs the core to listen on an address a container can reach, which the Ubuntu runner of CI does not set up for it. Shipping was measured in one process, without a network. The editor and the graph were tested in Chromium only (the browser that Playwright installs); Firefox and Safari were not tried. A service that is stopped and started again continues from its cursor (a test of the store, not of a restarted process).

Limits stated and left: the registry says `running` after a machine restart until the health probe of M8; the key of a deployment is not rotated; the core is one SQLite file with one writer, so shipping and the core's own runs wait for each other for the length of a commit; a run the core refuses for good (a conflict, a version mismatch) is logged by the service and left out, and nothing tells the administrator in the page.

## Retrospective

- Worked: the audit, again. Twenty gaps on paper, and two of them decided the code: the ingest key as a third key that belongs to no role (the route walk then proves it, with no special case in the test), and the cursor as a position in the log and not a copy of it (the case "the core lost data" became one line, `set(..., allow_back=True)`, and a test).
- Worked: building the page last, on the server functions. The graph, the scope of completion and the batch are functions a test calls; the browser tests are a few (23) and each checks one thing that only a browser can show (the 500 ms, the marker, the drawing, text that is not run as markup).
- Worked: a fake core that is a second database behind the real ingest service. The eleven scenarios of the outbox ran in milliseconds, and the one defect they found (the count lost when the network failed inside the loop) was found there and not in the acceptance test with two processes.
- Went wrong: the closing brace. Typing `${` gave no list because the `}` of the surrounding flow mapping was taken for the reference's own, and Monaco does not close a brace before a quote. Two rules (a regular expression for what may lie between the cursor and the brace; a `closed` flag the client writes from) and tests in a browser.
- Went wrong: a CSS rule hid nothing. `display: flex` beat the `hidden` attribute, so the graph pane was on the page before it was asked for. A global `[hidden]` rule and a test that looks.
- Went wrong: the CI guard against skipped browser tests failed on Ubuntu for the first story, because one test skipped when the editor was installed (it tested the page without the editor by not having it). It now blocks the vendor files with a route, so it runs everywhere.
- Went wrong, small: Playwright took ten seconds to carry a Cytoscape collection out of the page, so tests return nothing from their calls; and the test that compares the table of permissions with the spec had to learn about a permission that no role holds.
- Cost that should be said plainly: a service and a core that share nothing but HTTP means the first view of a shipped run lags by the idle wait (1 s) plus a round; the page does not refresh by itself; and the key travels in clear text unless TLS stands in front of the core, which is the deployment's job and is written in section 8 of the spec.
- Velocity: 21 SP planned and delivered. Work not in the plan: the vendor fetch script with its checks (it was in the audit), the `expected` field of the error item, the separate `GET /runs` of the service, and the benchmark.
- Next: M8 (recovery of unfinished runs at start, the health probe of services, the plan cache, the epoch fence and migration). The tag `m7` is to be created on `main` after this is merged.
