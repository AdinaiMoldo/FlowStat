# M5. Analysis

Status: in progress (started 5 November 2026). Size: 26 SP (US-18, US-19, US-21, US-22) + 5 SP (US-35, the feasible critical path).

## Goal

The designer is told about wrong types and about outputs that may not exist before anything runs, and the engine uses the same knowledge to start the steps that matter. A condition that compares a list with a number is an error at its column; a fan-in reference has the type of a list of what the instances produce; a reference to the output of a step that can be skipped is a warning with the condition that skips it, and no warning where the guard of the consumer implies the guard of the producer; a goal or a quorum that is not guaranteed is a warning with a value that shows it. The priority of a ready step is the longest chain behind it that can really run, not the longest chain in the graph. The analysis (C2) is checked against a reference interpreter that shares no code with it or with the engine.

## Readiness audit (5 November)

The milestone was checked against the Project Proposal (sections C1 phase 4, C2, the feasible critical path of C3, the oracle), against `dsl-spec.md` and against the code of M4 before the first line of code. Seventeen gaps were found. Each is closed in `dsl-spec.md` (sections 4 and 9 to 11) or in the order of work below.

1. **An action's interface has no element types.** The registry declares `list` for `rows`; US-19 needs `list<row>` to tell `check[*].rows` (a list of lists of rows) from one `rows`. Closed: the actions declare their parameters and outputs in the notation of the type language (`list<row>`, `list<list<row>>`); the Python type that the registry checks at run time is derived from it, and a test says they agree (spec 4, 9.3).
2. **Phase 4 cannot live in the compiler.** The Proposal puts type inference in C1, but it needs the signatures of the actions, which are above the compiler in the layers (`architecture.md`). Closed: the check runs in `analysis/types.py` after a successful compilation with the signatures passed in by the service, as the branch analysis of M4 does. The Proposal's "typing still runs when there are cycles" falls away: a document with a cycle has no plan to type. Written as a deviation.
3. **The pipeline has no place for errors from the analysis.** M4 made `findings` for warnings and notes. A type error must stop the publication. Closed: the analysis returns diagnostics of any severity; the service puts errors into `diagnostics` (which block) and the rest into `findings` (9).
4. **A foreach step would be checked nine times.** One line of text, nine instances, nine identical messages. Closed: types and availability are checked once per source step, through its first instance, and reported at the position of the text; identical messages are merged.
5. **The language has no type for what is unknown, and a type error must not cascade.** Closed: `any` (spec 4). An operand of type `any` gives `any`; an unknown action is not checked. US-18 requires that one mistake gives one message.
6. **Nothing says which mixes are errors.** `==` accepts anything at run time, `<` needs two numbers or two strings. Closed (9.2): an error where the run would fail or a declared type is broken; for `==` and `!=` between types with nothing in common a warning W-TYPE-005 (always false or always true), since `${inputs.amount} == '5'` is a typing slip that runs without failing.
7. **`T | error` and W-TYPE-002 are the wrong tool.** Spec 4 said reading the output of a step that may fail is a type error; the table had a warning for it. In the example `check` reads `load` and is fine, since `all_success` guarantees that `load` succeeded. Whether a read is safe depends on the join, which is availability. Closed: the output type has no `error` variant, W-TYPE-002 is retired, and `Av` (10) covers failed and skipped alike. The guard for an output that may be missing is `exists(...)` (3.1), and the analysis honours it (10.2).
8. **Required arguments are only checked when the action runs.** E-ACT-009 at run time; the designer finds out in production. Closed: E-TYPE-003 for a missing argument, W-TYPE-004 for one the action does not take (a typo that is silently ignored today). Tests that rely on E-ACT-009 at run time keep it through a workflow built to avoid the static check (an action without signature).
9. **`date` and `null` have no operators.** There is no date literal. Closed (4, 9.2): a date is passed through and compared with another date; `null` is compared with `==` and `!=` only. The Proposal's `T?` and the functions `round` and `coalesce` are not in the DSL (3) and are not added.
10. **The Proposal's `any_success` formula uses the guard, and `all_done` has "the common prefix".** `and over i of (not guard(P_i) or G_i(X))`. Re-derived at the audit: it is sound also when a predecessor fails, because `not guard` can only be true for a predecessor that did not succeed. Two changes: `not ran(P_i)` replaces `not guard(P_i)` (a predecessor behind a skipped step is absent too), and a step with no `on_failure: continue` at or above it has succeeded exactly when it ran, which gives the fact `ran(X)` to every descendant, including behind `all_done`, where the Proposal's "unconditional common prefix" would give none. Opaque parts are replaced so that the result stays sufficient. The oracle (gap 13) is the check. (A first reading of the audit treated a failed predecessor as unsound; the derivation above shows it is not, and the text of this point was corrected before any code was written.)
11. **`ran` already exists in another form.** M4 has the exact run condition inside the test generator (`analysis/generate.py`, `_conditions`). Closed: it moves to `analysis/runs.py` and the generator, the availability analysis and the priority use it. The prediction of a run (`analysis/predict.py`) stays the independent judge.
12. **"The number of elements a reference needs" is undefined.** Closed (10.3): a literal index into a group reference needs `i + 1`, `min` and `max` need one; the guaranteed number follows from the join rule and the members of the group. The whole-list use `${check[*].rows}` in the example needs none and gives no warning.
13. **The oracle does not exist.** The reference interpreter moved here from M4 (audit of M4, point 12). Closed: `tests/reference/` is written first, from the specification and a table of join examples worked out by hand, and shares no code with the engine, the scheduler or the analysis. It enumerates, for DAGs of at most six steps, a grid of input values (with boundaries) and the outcome of every step that can fail, and reports which steps started, succeeded, ran and were skipped. Three checks: soundness of `Av`, equality of the optimistic run with `ran`, and the feasible critical path (gap 16). Its own tests use the table, not the analysis.
14. **A reference inside `when` has no assumption to rest on.** Closed (10.2): `when(Y)` is what is being decided, so a reference in it is checked against `true`; a conjunct `exists(ref)` to the left of an `and` proves the reference to its right.
15. **Dead steps by inheritance and the warning for a missing `compensate` were promised to M5** (M4 and M3 journals). Closed: W-DEAD-001 extends to every step whose `ran` is unsatisfiable and names the first dead ancestor (10.4); W-COMP-001 (10.5) needs a flag on the action (`effect`) because a read has nothing to undo; `db.write`, `email.send` and `http.call` have it.
16. **The feasible critical path is not a story, and the priority policy is fixed in the scheduler.** The recount added 5 SP without a story, and `Scheduler` computes the plain longest path itself. Closed: the story US-35 (an issue on the milestone); the scheduler takes the priorities as an argument, the plain longest path stays as the baseline policy, and the feasible one is computed by `analysis/critical.py` (11). When the inputs of the run are known they are fixed in the conditions, which makes the priority that of this run; the Proposal computes it for all inputs. The cap on chains kept per step is 16; a cut gives a lower bound and the report says so.
17. **The benchmark of M2 had no branches.** The note on the priority rules says that M5 must use a generator with guarded branches and report against the table. Closed: `benchmarks/bench_critical.py` builds DAGs with mutually exclusive guards and compares FIFO, the plain path and the feasible path by makespan; whether the feasible path wins is not claimed before the measurement.

Left out on purpose: the completion scope for the editor (US-27, M7) beyond a function `available_at(plan, step)` that M7 will call and a test of it; nullable types; checking an approval answer against `decisions` (REST, M6); the cache of unchanged prefixes after an edit (NFR-01 is measured in M9).

7. Review, retrospective, tag `m5`.

## Progress

- 5 Nov: readiness audit and rules written.
- 5 Nov: reference interpreter done (`tests/reference/interp.py`), before any analysis: the join rules, the meaning of guards, the enumeration of input grids and failing steps, the longest chain that ran. Its own tests: a table of 20 join examples worked out by hand, the meaning of 11 guards, the example of the Proposal (21 s plain, 11 s feasible). The engine agrees with it on 1,920 step states of random workflows with failing steps (4 seeds x 120 workflows x 4 runs), so the two readings of the specification are the same.
- 5 Nov: US-18 and US-19 done: `analysis/types.py` (the type language, subtyping, inference of conditions and arguments), the actions declare their types in the notation of the DSL (`list<row>`), the service compiles and then checks the types (errors block, warnings are findings). 86 unit tests and 7 acceptance tests; 600 random guards are compared with the evaluator of the reference interpreter (what is accepted never fails for a type reason, what fails for a type reason was reported). Seven deliberate faults in the checker each make tests fail, except skipping the second instance of a foreach step, which the merge of identical messages also covers.
- 5 Nov: US-21 and US-22 done: `analysis/runs.py` (run conditions, bounds), `analysis/availability.py` (what is guaranteed at each step, references, groups, goals, dead steps by inheritance, W-COMP-001). 31 unit tests and 6 acceptance tests. Two checks against the reference interpreter: when a step starts and a fact holds, the step it names has succeeded (4 seeds x 150 workflows x 8 runs with failing steps; seed 0 checked 1,377 facts, 242 of them not trivially true), and when nothing fails the steps that run are exactly those whose run condition holds. Two deliberate faults (`not low` in place of `not high` for the quorum rule; dropping the fact that a step with no continue above it succeeded iff it ran) each fail the tests. The card `algorithms/C2.md` comes with the measurement.
