# M2. Engine

Status: in progress (started 5 November 2026). Size: 38 SP (US-06 to US-12).

## Goal

A compiled plan runs: independent steps overlap in time, conditions, the four join rules, approval waits, contracts and goals decide the state of every step and the outcome of the run, every step has a recorded history, and the example `quarterly_consolidation` runs end to end on sample files of the nine regional offices from a command line.

## Stories

| Story | Function | SP | Given / When / Then |
| --- | --- | --- | --- |
| US-06 parallel steps | C3 | 8 | Given a and b are independent, c needs both and m = 2, when I run, then a and b overlap in time and c starts after both succeed |
| US-07 skips, failures, quorum | C3 | 8 | Given b has a false `when`, c needs b (all_success) and d needs b (all_done), then b and c are SKIPPED and d runs. Given 9 loads, 2 failing and `at_least: 7`, then consolidate runs; with 3 failing it is UPSTREAM_FAILED |
| US-08 approval | C3 | 5 | Given a run reaches `approval.wait`, then it is WAITING and releases its slot. When I answer rejected, then the step is SUCCEEDED with decision rejected and the branch guarded by that decision runs |

| US-10 contract on output | C3, C1 | 3 | Given `ensures: publish.written > 0` and an action that writes 0 rows, then the step fails with a contract violation |

## Readiness audit (5 November)

The milestone was checked against the Project Proposal before the first line of code. Every requirement it touches has a story and every story has a criterion. Six gaps were found; each is closed in `dsl-spec.md` (section 3.1) or in the order of work below.

1. The runtime meaning of expressions was not written down (what `+` does on text, whether `and` needs booleans, what a missing field is). Closed: section 3.1 of the DSL specification, with the error codes E-RUN-001 to E-RUN-008.
2. The value of `${check[*].rows}` when some instances failed was not defined. Closed: a fan-in reads the instances that SUCCEEDED, in declaration order; failed and skipped instances are left out. This is what makes `at_least: 7` usable.
3. Reading a field of a step that has no output (failed, skipped, cancelled) was not defined. Closed: it is an error E-RUN-002 inside an expression, and `exists(${x.field})` is the guard that answers false instead.
4. "Declared schema" of an action output (US-12) has no place in the DSL yet. Closed: the schema is declared by the action in its adapter (registry in B6), checked by the engine when the action returns; the workflow text does not repeat it. Type inference over these schemas stays in M5.
5. The state machine of a step lists ten states, but M2 reaches only seven (COMPENSATED and the two compensation states belong to M3). The state table is written with the engine so that M3 adds states without changing the scheduler.
6. Determinism of the engine (CLAUDE.md): time, identifiers and the seed are arguments. The scheduler is written as a pure state machine (events in, commands out) and the thread pool is a thin driver around it, so every test of the four join rules runs without threads and without sleeping.

2. Tests, then the expression evaluator (`engine/evaluator.py`), checked against Python on random expressions.
3. Tests, then states and events (`model`), then the scheduler core: ready heap with the plain longest path, `when`, four join rules, quorum, skips, upstream failures, waiting, signals, contracts, cancellation, goals and outcome. Property tests on random DAGs for the invariants of the Proposal.
4. Event history (A2, `repo`) and the run service on top of the workflow service.
5. Actions of B6 (`xlsx`, `db`, `stats`, `statguard`, `approval`) and the command-line runner.
6. Benchmark: FIFO against plain longest path on generated DAGs (baseline for the feasible path in M5), algorithm card C3 level 1.
7. Review, retrospective, tag `m2`.
