# M1. Language core

Status: done (5 November 2026, tag `m1`). Size: 26 SP (baseline). The parser and the shape validator were added to the milestone on top of it (6 SP, recorded in the backlog as added scope on 5 November).

## Goal

A workflow file is read, checked and compiled into a plan (a static graph), with every error reported with a line and a column.

## Stories

US-01 to US-05 of the Project Proposal (version store, catalogue, YAML reading, compile phases, foreach expansion). Acceptance criteria are copied here from the Proposal when the milestone starts.

## Order of work

1. Readiness audit against the Proposal.
2. `dsl-spec.md` closed (open points at its end).
3. Tests, then lexer, then parser with error nodes.
4. Tests, then shape validator with did-you-mean.
5. Tests, then compiler phases 0 to 3.
6. Measurement of compile time against file size (NFR-01) and the card of C1 level 1.
7. Review, retrospective, tag `m1`.

## Progress

- 3 Nov: expression lexer done, tests first (21 tests, 100% coverage of `dsl/lexer.py`): positions mapped to the original file, errors reported without stopping, 2000-case random test of the invariants.
- 3 Nov: expression parser done, tests first (62 tests): precedence climbing, error nodes, recovery at synchronisation tokens, depth limit of 128. Checked against Python on 3000 random arithmetic and boolean expressions (same value), round trip through `to_source`, and a 3000-case fuzz test (never raises). Coverage of `dsl/` 99%.
- 3 Nov: YAML reader with positions (B1, `ruamel.yaml`) and the table-driven shape validator done, tests first: 37 golden documents with exact line and column, did-you-mean by edit distance. The test against `examples/quarterly_consolidation.yaml` found an invalid YAML in the example itself (unquoted `[load[region]]`); fixed.
- 3 Nov: compiler phases 0 to 3 done, tests first: foreach expansion with source map (the main example gives 22 steps), references and quorum checks, Tarjan and shortest cycle (found and fixed a bug through the naive oracle), ancestor bitsets, 12 reference error codes. Compile time measured: 161 ms for 200 steps. Algorithm card C1 filled.
- 5 Nov: version store and catalogue repository on SQLite (US-01, US-02, tests first, 18 tests): published rows are immutable through database triggers, so a bug in the code above cannot change a version. Input `ref` to a catalogue list (E-REF-012, E-REF-014), the plan carries the input specs, `validate_inputs` checks run values (E-INPUT-001 to 005). The workflow service saves drafts with diagnostics and publishes with a catalogue snapshot; a published version reads its own snapshot, never the live catalogue.
- 5 Nov: acceptance tests of the five stories written from the Given/When/Then criteria. The one for US-03 found that the YAML library reports a missing colon on the next line; the reader now reports the line where the key starts.

Changes against the plan, all decided during the work:

- The parser and the shape validator are ours (no Lark, no jsonschema); they were not in the 26 SP baseline.
- New diagnostics beyond the first draft of `dsl-spec.md`: E-REF-014 (`ref` on a non-string input), E-VER-001 and E-VER-002 (the `version` and `workflow` in the text must agree with the version being published), E-INPUT-001 to 005 for run values.
- The `version` line is part of the document, so after publishing v2 the designer must write `version: 3` in the new draft before it can be published. Chosen over rewriting the designer's text silently.
- A new package `service` on layer 7 holds the orchestration (repo plus compiler); the layers table is updated.

Not done in M1 and moved: type inference (phase 4) stays in M5 as planned.

## Retrospective

- Worked: tests before code with a naive oracle. The oracle for cycles found a real bug (a self-loop was missed by the shortest-cycle search), and the acceptance test of US-03 found a wrong line number that no unit test had looked at. Writing the acceptance tests from the exact words of the criteria is worth doing at the start of a milestone, not at the end.
- Worked: golden documents with position markers; every diagnostic is checked for line and column.
- Went wrong: the main example of the Proposal was invalid YAML (an unquoted `[load[region]]`); it was found only when the compiler ran on it. Every example in a document needs to be parsed by the real code.
- Went wrong: one push failed the lint step of CI again (a long line in a script). The lesson from M0 was applied to `src/` and `tests/` but not to `scripts/` and `benchmarks/`. Next: run ruff and mypy on the whole repository, as CI does, before every push.
- Went wrong: an unknown catalogue list produced a second, derived error (a quorum larger than the number of dependencies). Errors that are only a consequence of an earlier error must be suppressed; the check was added.
- Velocity: 26 SP planned and delivered, plus 6 SP of parser and validator work. The plan was recounted on 5 November: 203 SP baseline, 214 SP planned (see `backlog.md`).
- Next: M2 starts with the readiness audit against the Proposal, then the tests of the scheduler (C3) before any code.
